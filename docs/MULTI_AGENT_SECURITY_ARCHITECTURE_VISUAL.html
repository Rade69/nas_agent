4. Multi-agentski radni tok

Claude Code

Glavni agent za faze, arhitekturno centralne izmjene i sigurnosno-kriticne slojeve.

Codex

Ciljane izmjene, review, dokumentacija, verifikacija i male izolovane popravke.

pi agent / OpenRouter

Paralelni audit/refactor zadaci preko vise LLM modela, uz jasne report fajlove.

Workflow koji sprecava sudare

  1. Agent prvo radi git status i git log.
  2. Prije izmjene simbola radi se GitNexus impact analiza.
  3. Agent dira samo svoj scope i ne stageuje tudje izmjene.
  4. Svaki zadatak dobija agent_reports/ izvjestaj.
  5. Tracker u docs/MIGRATION_PLAN.md ostaje izvor istine za faze.
  6. Mali commitovi cuvaju trag ko je sta uradio.

5. Granice odgovornosti

React ne upravlja OS-om

Renderer prikazuje UI i voice state. Ne dobija filesystem, shell ili OS moc.

Electron je tanak shell

Prozori, IPC i Python process manager. Nova agent/storage/AI logika ne ide u electron/main.cjs.

Python je sigurnosna granica

Tool executor, permission engine, confirmation binding i audit log odlucuju sta se smije izvrsiti.

6. Kako to objasniti za 60 sekundi

Kratka prica

Ovo je lokalni Windows AI companion. UI je u React/Electronu, ali opasne odluke i alati idu kroz Python backend. Svaki tool ima risk, Computer Mode, confirmation i audit log. Vise agenata razvija isti projekat, ali GitNexus, mali commitovi, tracker i agent_reports cuvaju red.
